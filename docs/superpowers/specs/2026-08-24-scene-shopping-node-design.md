# 场景导购独立节点设计

## 目标

把“去爬山有什么推荐”“去三亚旅游带什么”从普通商品搜索中拆出，输出按场景任务组织的、跨品类且可解释的商品清单。

## 入口与边界

- Governor 识别到 `scene`，且用户未明确指定品类或子类时，路由为 `scene_search`。
- 已指定子类的请求保持普通检索。例如“爬山背包”仍只找背包。
- 购物操作、单品追问、品牌硬筛选继续沿用现有链路，不进入场景节点。

## 新节点职责

新增 `scene_plan` 节点，位于 Governor 之后、retrieval 之前。它不调用模型，负责：

1. 根据 `scene` 读取场景计划：场景名称、注意事项、任务槽位、每个槽位允许的真实子类和检索关键词。
2. 为每个任务槽位建立独立检索查询，并将查询写入状态，以便后续检索与追踪。
3. 场景未知时使用现有关键词扩展作为兼容降级。

第一期计划：

- `outdoor`：徒步鞋、背包、防晒、功能饮料。
- `travel`：防晒、短袖 T 恤、背包、移动电源。
- 其余已存在场景复用关键词映射，先不强制任务槽位覆盖。

## 选品与多样性

场景检索按任务槽位分别召回，再以商品 ID 去重。每个槽位保留其最佳候选；最终最多展示三个任务槽位的商品。这样在评分前就已保证覆盖，不再依赖精排后的子类轮转。

若一个任务槽位无候选，跳过该槽位并记录到 trace；不以不存在的商品补齐。

## 回答与降级

新增场景专用回答构建器：

- 首句说明场景与准备思路。
- 每个商品标明所属任务，例如“脚下保护”“防晒防护”“补水补能”。
- 只引用检索证据中的商品、价格和属性。
- 场景计划内的注意事项只作为通用准备建议，不伪造成商品属性。

场景专用提示词独立放在 `app/prompts/scene_response_prompt.py`，并强制：

- 用 `scene_task.label` 组织输出，而不是普通 Top-1/Top-2 排名；
- 每项必须同时出现任务标签、完整标题和准确价格；
- 没有证据的任务、参数、容量和功能不得补写；
- 模型输出缺少任一候选商品或任务标签时，切换到相同结构的确定性模板。

当聊天模型不可用、返回空文本或未引用商品时，使用同一结构的确定性场景回答，不降级成普通 Top-3 文案。

## 数据流

```text
Governor(scene_search)
  → ScenePlanNode(scene plan + task queries)
  → RetrievalNode(per-task recall + ID 去重)
  → Reranker / Evidence / Decision
  → SceneResponse(scene-specific prompt or deterministic fallback)
  → Guard
```

`AgentState` 增加 `scene_plan` 与 `scene_task_queries`，SSE 最终结果沿用现有完整状态载荷；Android 无需新增接口字段即可展示商品卡片。

## 失败处理

- 模型不可用：场景识别、场景计划、检索和确定性回答都可在规则链路运行。
- 某个任务无商品：跳过该任务，保留其他有证据的任务，不编造替代品。
- 全部任务无结果：使用现有“无匹配商品”回复。
